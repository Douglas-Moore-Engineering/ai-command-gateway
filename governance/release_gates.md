# Release and exposure boundaries

Current disposition: documentation repository only. Discovery review is pending. Candidate requirements and metrics are not an approved technical baseline.

Before offline application implementation: review scope/responsibility and affordability; qualify source data and policy inputs; plan V&V and applicable governance/standards controls. Before evaluation: freeze expected decisions, protocol and thresholds. Before any cloud/site exposure: obtain specific authorization, approved data flow, identity/network design, cost basis and required readiness reviews.

Engineering qualification, AI governance authorization, customer acceptance and production release are separate decisions. None is recorded as passed. Future protected promotion must bind real reviewer authority and immutable versions and be tested against bypass; written rules do not enforce branch protection. Lifecycle/control-coverage checks are pending technical baseline work, not represented as setup-check outcomes.
